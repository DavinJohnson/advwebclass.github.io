Source: Open Library Book JSON (Fantastic Mr. Fox)

Main structure

The whole file is one JSON object describing a single book edition. There is no top-level array – plain fields, arrays, and nested objects are all mixed together as properties of that one object.

Main keys

title, authors, publishers, isbn_10, isbn_13, identifiers, publish_date, number_of_pages, languages, source_records, type, first_sentence, created, last_modified

Simple values (text or number)

  • "title": "Fantastic Mr. Fox" – string
  • "number_of_pages": 96 – number
  • "publish_date": "October 1, 1988" – string

Values that are collections (arrays)

  • "publishers": ["Puffin"]
  • "isbn_13": ["9780140328721"]
  • "contributions": ["Tony Ross (Illustrator)"]

Values with structured data inside (objects)

  • "type": { "key": "/type/edition" }
  • "first_sentence": { "type": "/type/text", "value": "Down in the valley there were three farms." }
  • "identifiers": { "goodreads": ["1507552"], "librarything": ["6446"] } – an object whose own values are arrays

Nested objects / arrays

authors is an array that contains an object – two levels of nesting in one field. identifiers nests the other direction: an object containing arrays.

Overall organization

It reads like a typical REST API record: a flat set of descriptive fields (title, page count, dates) sitting next to arrays for anything that can repeat (publishers, ISBNs, source records) and small objects for anything that needs its own type/value pair or its own sub-keys (identifiers).

Examples

Name/value pair

"title": "Fantastic Mr. Fox"

Object

"identifiers": {
  "goodreads": ["1507552"],
  "librarything": ["6446"]
}

Array

"isbn_13": ["9780140328721"]

Nested structure

"authors": [
  { "key": "/authors/OL34184A" }
]
